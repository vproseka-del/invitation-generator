# Negative Style

Negative Style — независимый инспектор качества текста.

## Роль

Negative Style **не участвует в генерации** и **ничего не исправляет**. Он работает после генерации, проверяет черновик по установленным правилам и только сообщает о найденных проблемах.

```
Core + Context + Project Arguments
              ↓
          Черновик письма
              ↓
       [ Negative Style ]
              ↓
          Отчёт о проблемах
              ↓
       Финальная версия
```

## Структура

- `rules.json` — база правил проверки (единственный источник истины);
- `README.md` — настоящее описание.

## Формат правила

Правило — это JSON-объект в массиве `rules`. Поля:

| Поле | Назначение |
|---|---|
| `id` | Уникальный идентификатор правила (например, `NS-001`) |
| `category` | Категория правила: `forbidden_phrase`, `undesirable_pattern`, `placeholder_unfilled`, `structure` |
| `severity` | Уровень серьёзности замечания |
| `source` | Источник правила: `Negative Style`, `Core`, `Context`, `Project Arguments` |
| `match` | Тип проверки: `substring`, `regex`, `required_element` |
| `pattern` | Искомый текст, регулярное выражение или имя обязательного элемента |
| `message` | Текст замечания |
| `recommendation` | Рекомендация по исправлению |
| `case_sensitive` | `true` — проверять с учётом регистра (по умолчанию регистр игнорируется) |
| `status` | `active` — правило применяется; иное значение — правило выключено |

## Уровни серьёзности

- `error` — критическая ошибка (незаполненные плейсхолдеры, отсутствие обязательных элементов);
- `warning` — нарушение правил стиля или проекта;
- `recommendation` — рекомендация по улучшению без фиксации нарушения.

## Источники правил

Каждое замечание ссылается на источник правила, чтобы пользователь понимал, какое правило стало основанием:

- `Negative Style` — общие правила качества текста (запрещённые обороты, нежелательные конструкции);
- `Core` — подтверждённые принципы авторского стиля (ядро VIV_STYLE);
- `Context` — ограничения контекстного профиля;
- `Project Arguments` — ограничения проекта (обязательные элементы, плейсхолдеры, объём).

Сейчас `Core` и `Context` пусты и будут наполняться по мере подтверждения признаков стиля.

## Итоговая оценка

- `passed` — текст соответствует правилам;
- `passed_with_warnings` — есть предупреждения, но критических ошибок нет;
- `failed` — есть критические ошибки.

Итоговая оценка позволяет в будущем использовать инспектор автоматически перед массовой рассылкой.

## Как пополнять

Правила добавляются в `rules.json` без изменения кода: приложение читает базу при каждой проверке.
